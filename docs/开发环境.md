# 使用 mise 配置开发环境

项目使用 Python 标准库，没有需要通过 pip 安装的第三方依赖。仓库根目录的 `mise.toml` 固定 Python 3.13.16，与 CI 的 Python 3.13 主版本一致；插件最低仍支持 Python 3.10。

## 初始化

在仓库根目录执行：

```sh
mise trust mise.toml
mise install python
mise exec -- python --version
mise tasks ls
```

日常使用 `mise run` 或 `mise exec` 即可获得项目指定的 Python。若希望进入目录后终端自动切换版本，可按 [mise 官方说明](https://mise.jdx.dev/cli/activate.html) 配置 shell 激活；已经激活 mise 的终端无需重复配置。

## 常用命令

| 命令 | 用途 |
| --- | --- |
| `mise run check` | 运行全部程序测试，并查看默认合成案例数量；不调用外部模型 |
| `mise run test` | 单独运行 unittest 回归测试 |
| `mise run evaluate` | 查看默认合成命名案例数量 |
| `mise run doctor` | 只读检查 Python、Codex CLI 和 App Server 连接 |
| `mise run title -- status` | 查看本地命名配置与记录数量 |
| `mise run archive -- status` | 查看本地归档策略配置 |

任务参数会传给对应 Python 入口，例如只检查语言案例：

```sh
mise run evaluate -- --cases tests/fixtures/naming_language_cases.json
```

实际调用模型必须显式添加 `--live`，会消耗当前账号额度。例如：

```sh
mise run evaluate -- --cases tests/fixtures/naming_language_cases.json --live --workers 2 --output docs/naming-language-evaluation.json
```

`title` 和 `archive` 是现有 CLI 的入口，具体子命令及是否调用模型仍遵循各自规则，可用 `mise run title -- --help` 和 `mise run archive -- --help` 查看。

## Codex 与后台 Hook

运行测试和查看案例数量只需 Python。`doctor`、实际命名及归档扫描还需要可用的 Codex CLI 与 App Server；实际模型调用需要账号已登录。程序沿用现有 Codex 查找规则，macOS 优先使用桌面应用自带的可执行文件，也支持 PATH 或插件的 `codex_bin` 配置。

mise 配置用于当前仓库的开发环境。安装后的插件 Hook 沿用现有 `python3` / Windows `py -3` 入口，其宿主进程需能找到 Python 3.10+。本地 `check` 或 `doctor` 通过不能代替真实 Hook 触发、模型评测或桌面显示验收，详见 [发布验收](发布验收.md)。
